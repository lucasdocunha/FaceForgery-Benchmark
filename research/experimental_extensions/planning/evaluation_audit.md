## Exact SRM contract

The brief's six-channel definition is correct. `src/data/data.py:188` constructs ImageNet-normalized RGB before the SRM branch at line 267, which concatenates that RGB with three residual channels. `src/forensics/srm.py:60` takes weighted luminance of the normalized RGB, convolves with the exact three fixed 5x5 filters using zero padding 2, clamps to `[-3,3]`, and divides by 3. Reuse `extract_srm_residuals` with one-image semantics and require the effective checkpoint channel count to match.

Do not reinterpret this as raw RGB residual extraction, 30 filters, or residual-only input. Verify against the actual `ImageDataset`, including JPEG decoding, resize from a non-square image, channel order, constants, impulse/checkerboard images and a deliberately saturated fixture. The statement that TLU almost never activates is an empirical frequency claim, not proven by code and not needed for equivalence. Use CPU FP32 for the exact-equivalence test, with the existing `2e-6` tolerance in `tests/robustness/test_encoding_compat.py:25`; test output independence from inference batch size and order.

DTCWT is a small optional follow-on adapter using `extract_dtcwt_features(..., mode="directional_only")` on normalized RGB, producing nine channels. Preserve one-image extraction: its per-channel min/max at `src/forensics/dtcwt_module.py:70` spans the whole supplied batch, so calling it on several images changes legacy semantics. Missing `dtcwt` already raises at line 28 and must remain explicit.

## Small proposed APIs and integration order

1. Extend `summary` and `choose_threshold` in place. EER is the piecewise-linear ROC crossing where `FPR = 1 - TPR`; record this convention. It is a diagnostic computed from target labels, never an operating threshold for deployed accuracy. Single-class AUC/AP/EER are `null` with a status, not 0 or 0.5. Fake-positive F1 uses the frozen threshold and an explicit zero-division policy. Confusion axes are true/predicted `[real,fake]`, normalized by true-class rows, with absent-class rows marked undefined.
2. Extend `calibrate(..., policy=...)` without changing existing callers' balanced-accuracy default. Youden `TPR + TNR - 1` and balanced accuracy `(TPR + TNR)/2` have the same optimizer under identical candidates and ties. Keep both names available and record the chosen one. Use the current `>=` rule and smallest-threshold tie break, including its finite sentinel just above 1. Freeze each score system's calibration; never average member thresholds as an ensemble calibration.
3. Add a strict model adapter returning the existing finite two-logit contract and an input/score identity. Initial adapters wrap `load_model_from_run` and `load_pilot`. New experiment owners provide model construction and scoring through the same adapter interface. VLM target-label sequence log probabilities become a two-way softmax. Reconstruction/centroid anomaly scores need a declared fixed transformation, or a validation-only probability mapping, and should retain raw scores for diagnostic rank checks. Threshold-only calibration does not make anomaly scores calibrated probabilities.
4. Add `TargetSpec(name, manifest, root, primary_unit, breakdown, real_reference_policy)` and `evaluate_suite(model_adapter, frozen_calibration, targets, output, ...)`, calling existing `evaluate` for each target. Load the checkpoint once. Validate all target certificates/config before execution, create fresh per-target directories and a suite status/index, and fail the suite if any required target fails. A dry run validates schemas without loading models or decoding benchmark images. Configured subsets of the four targets are allowed; the full server matrix requires all four. Pilot/proxy names and scope must be explicit.
5. Extend `evaluation_report` with uncertainty and add a small plotting module consuming those same certified scores. Write ROC coordinates plus ROC, score-histogram and normalized-confusion PNGs with target/unit, frozen threshold and class names. Hash these in the completion status. Do not emit JSON infinity for the ROC sentinel. Plot once per population, outside the inference loop.
6. Add legacy `research_run` metadata and unit-aware seed summary. Keep the exact canonical set `[42,123,2024,7,2025]` in the new matrix. Hash scientific settings with only declared nonscientific paths and seed removed; retain seed/checkpoint bytes on each realization. Legacy absent training hashes must stay explicitly unverified rather than being fabricated from current manifests. Add the HPC evaluation job and a portable wrapper after the CLI works on synthetic fixtures.

Input/score identity should cover checkpoint(s), original/effective config, representation/filter definitions, image size, normalization, channel order, class polarity and score mapping. Current calibration binds only checkpoint bytes and class polarity; the same CNN weights at a different resolution could otherwise inherit an invalid threshold. `provenance.source_identity:83` hashes only `src/robustness/*.py`, so include hashes for reused legacy dataset, SRM, rebuild and model helpers in legacy adapter provenance. Evaluation must record calibration-file hash, inference precision and source identity in addition to existing manifest/checkpoint hashes.

DF40 source-matched comparisons should remain the audited default when annotations exist. To reproduce the historical 24-technique/6-paradigm local-subset protocol, allow explicit `pooled_all_real` references and disclose this source-confounded design. Without reviewed reference annotations, report subgroup fake recall/counts, and mark unavailable source-matched AUC. Do not silently relabel pooled reals as matching every generator. Subgroups reuse real references and are not independent repetitions.

For MFFI/Test-D, use the same dataset namespace and logical image IDs while changing split/root: `convert_manifest` intentionally excludes split from `sample_id` at line 151. Assert identical paired IDs, labels and group IDs; report image hashes separately because degraded bytes differ. MFFI has no video/identity columns, so its available intervals are image-resampling intervals with unresolved dependence, not certified identity-cluster intervals. Celeb extraction already uses namespaced full video paths and verified inverted official labels (`scripts/prepare_celeb_df.py:31,131`); preserve the extraction/list hashes, video coverage and frame-count audits.
