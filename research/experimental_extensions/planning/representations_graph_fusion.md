The lead owns CLI, shared config and evaluator integration. Use a separate objective-aware trainer for cached features and graphs; do not force SupCon or graph masks into image CE batches. All artifacts bind config, git commit, implementation hashes, seed, data/cache hashes, selected checkpoint, preprocessing, training-label provenance and score orientation. Checkpoints also persist optimizer/scheduler/RNG state, feature normalization, projection/centroids, graph specification and any rebuild state, routing policy and expert dependencies. Full-scale commands must use configurable roots and list every dependency needed for a fresh-machine inference round-trip.

**Frozen feature cache contract.** An immutable versioned directory contains `cache.json`, keyed row metadata, memory-mappable feature shards and float32 two-class logits, plus checksums and a completion marker written only after success. Use `sample_id`, not loader position, as identity; preserve `group_id`, split, image SHA-256, optional video/source identity and provenance. The feature API should expose no labels to graph construction; labels join through an explicit fit mask or evaluation manifest.

The content key covers checkpoint bytes, full run config, canonical manifest bytes, image-content inventory, preprocessing/SRM implementation and parameters, extraction layer/schema, package versions, computation/storage dtype and view definition. Changing any dependency invalidates reuse. Missing, duplicate, extra, corrupt or nonfinite rows fail, with no intersection-based alignment or image substitution. Atomic writes and per-key locks prevent partial/concurrent reuse. Arrays and checkpoints stay outside git.

Define the default penultimate feature as input to the final classification linear layer in evaluation mode: DINO after classifier LayerNorm, CLIP pooled representation, ResNet pooled vector and MobileNet after classifier hidden activation. Record layer path and dimension; do not silently substitute a backbone's differently normalized `forward_features`. Verify reconstructed final-linear logits against the original forward and direct versus cached inference on fixed fixtures. Additional raw pooled features require a separately named schema. Keep backbone parameters frozen, dropout disabled, no autocast-dependent cache mixing, and softmax in float32. Requesting stochastic views or SBI uses a separate view ID, source ID, seed, augmentation hash and generated-content hash; a single deterministic feature per image is not an augmented two-view recipe.

Dependencies before reuse: verified checkpoint inference, exact legacy SRM equivalence in Stack B, strict image loading, and canonical prediction export. In particular, do not route caches through the legacy unreadable-image substitution behavior.

## G: projected SRM baseline ladder

Use seed 42 first, one verified SRM backbone at a time: cheap MobileNet smoke, then DINO and CLIP. Concatenation follows only if individual features justify it. Freeze the backbone; train a small MLP projection with 128/256-dimensional L2-normalized output. Compare in this order on identical train/validation IDs:

1. Original checkpoint logits, unprojected real/fake centroids and cosine k-NN.
2. Regularized logistic probe, then a small CE MLP on the same cached features.
3. SupCon projection with class-balanced batches; score projected features by train-only centroids, k-NN and a separately fitted linear probe.
4. A bounded hard-negative weighting ablation; optional cached genuine/SBI views once the SBI path is validated.

[SupCon, NeurIPS 2020](https://proceedings.neurips.cc/paper/2020/hash/d89a66c7c80a29b1bdbab0f2a1a94af8-Abstract.html) motivates multiple same-class positives and normalized embeddings. Use the outside-log average over positive log probabilities, exclude self-pairs, and require at least two distinct examples per class in a batch. A class-balanced sampler avoids empty positive sets; do not also apply class weights. Stable log-sum-exp and FP32 loss math are required. Frozen feature projection is an adaptation, not a reproduction of end-to-end SupCon.

[Robinson et al., ICLR 2021](https://arxiv.org/abs/2010.04592) study unsupervised hard-negative sampling with controllable hardness. Here true training labels are available: restrict negatives to the opposite class, use detached bounded weights proportional to `exp(beta * cosine)` with per-anchor mean one, and retain `beta=0` as exactly the ordinary SupCon denominator. This is an explicitly named supervised adaptation. Do not import their unknown-class correction unchanged. Mining can amplify label errors and compress diverse fake mechanisms; default hardness is zero until the ablation helps.

Fit all standardization, centroids and probes on training rows only. Fix fake-score polarity analytically: cosine-to-fake minus cosine-to-real, or distance-to-real minus distance-to-fake; a fixed monotone mapping yields a bounded score for the shared evaluator. With normalized samples and normalized centroids, squared Euclidean and cosine ranking coincide, so they are diagnostic views, not independent model evidence. Report AUC/F1/accuracy/EER and paired validation complementarity against checkpoint logits. Silhouette and seeded subsampled t-SNE are diagnostics only; never select on their separation. Label projected distance scores as uncalibrated unless a documented source-validation calibrator is fitted.

## H: graph validity and scalability

**Label budget.** HF checkpoints were trained with all MFFI training labels, according to the brief. Calling a 5% GNN on those features a 5%-label end-to-end method would be false. Report it as low-label downstream adaptation on a fully supervised representation. A genuine label-efficiency control uses a general/self-supervised backbone never fine-tuned with MFFI labels, or retrains every supervised component on the same selected label mask. This includes G's projector, scalers using labels, centroid/probe fits, and graph metric adaptation. Reusing a fully supervised SupCon head cannot repair this limitation.

Create nested, seeded, class-stratified training masks for 1/5/10/25/100%, hashed by stable source ID with actual counts recorded. The same masks feed logistic regression, MLP, k-NN, label propagation, Correct-and-Smooth and every GNN. Labels outside the selected train mask must not enter losses, sampling priorities, edge construction, propagation seeds, residual corrections, class weights or normalizers. Validation labels are separately disclosed selection supervision, not part of the advertised training budget. Group all views of a source together; absent identity/video annotations remain an unresolved dependence limitation.

Mandatory graph comparisons are shallow logistic/MLP, k-NN, [local/global-consistency label propagation](https://proceedings.neurips.cc/paper_files/paper/2003/hash/87682805257e619d49b8e0dfdc14affa-Abstract.html), and [Correct-and-Smooth](https://arxiv.org/abs/2010.13993), whose residual seeds and label clamping use only selected train labels. Compare two-layer [GCN](https://arxiv.org/abs/1609.02907), [GAT](https://arxiv.org/abs/1710.10903), and [GraphSAGE](https://proceedings.neurips.cc/paper/2017/hash/5dd9db5e033da9c6fb5ba83c7a7ebea9-Abstract.html). These papers motivate architecture/baseline choices, not expected success on forensic cosine graphs. Prefer GraphSAGE for the first scalable path; GAT's edge attention is an extra memory cost to measure.

**Graph definition.** L2-normalize finite nonzero features, retrieve cosine top-k with deterministic ID tie breaks, exclude self-neighbors, and record directed/symmetric-union/mutual policy. Default `k=10`, then 5/20 only for survivors. Store sparse integer edges and explicit nonnegative weights, such as `(1+cosine)/2`, with consistent duplicate/self-loop handling and normalization. Log degree distribution, isolated nodes, connected components, neighbor similarity and train-mask homophily. Never infer edge quality using hidden labels during selection.

Static cached embeddings produce a static graph. The dynamic variant learns a small input projector from the permitted labels, detaches embeddings and rebuilds neighbors at a recorded interval, initially every five epochs. No differentiation through neighbor selection; no per-minibatch global rebuild. Freeze projector and rebuild rule before final evaluation, persist graph hashes, and avoid stale `GCNConv(cached=True)` normalization across rebuilds. The fixed graph is a required ablation.

| Protocol | Permitted information and behavior |
| --- | --- |
| Inductive source-reference, primary | Fit projector, normalizers, graph and model on source training data. At validation/target inference, attach each query only to source neighbors; queries neither connect to one another nor update source states. Use directed query ego-graphs with source-only neighbors at every layer. Query predictions must be invariant to other target rows and batch composition. GraphSAGE is the first implementation; GCN/GAT require explicit directed normalization tests, not a silent symmetric-graph fallback. |
| Transductive batch inference, separate result | After all choices are frozen, construct a source-plus-one-target-population graph from features only. Target-target edges and collective propagation are allowed; target labels remain inaccessible. Use the same protocol on source validation for development, and disclose that scores depend on the target population. This is not a pure inductive or per-image zero-shot result. |

Never combine Test, Test-D, DF-40 and Celeb-DF nodes into one final graph. Clean/degraded counterparts share logical IDs and must be separate graph artifacts. Full transductive retraining with target features is outside the initial implementation: it requires its own predeclared optimization/selection protocol. Oracle cross-class edge injection is a separate, frozen stress test, with outputs ineligible for model selection. Random rewiring can be the label-free robustness ablation. Report 0/10/30% edge replacement and k variation only after the default works.

**Scale calculation.** Dense similarities cost `4*N*N` bytes in FP32 even before top-k or gradients. At 524,429 train nodes this is 1,024.55 GiB; at 853,739 train+val+test nodes it is 2,715.25 GiB. Blocked exact search saves peak memory, not quadratic arithmetic, so it is not the full-scale default. Directed k=20 edges stored as two int64 indices plus one float32 weight cost about 200.05 MiB for train and 325.68 MiB for all three splits, before symmetrization, framework copies and message activations. The combined count is a capacity example, not permission to mix splits during training.

Use bounded query/reference tiles and running top-k for min pilots; reject exact graph construction above an explicit default 10,000-node limit. Servers use an optional approximate index over 128/256-dimensional features, sparse propagation and bounded two-hop neighbor sampling. Configure CPU threads, index memory and build cadence. Record recall@k against deterministic exact-query subsets, build/query time and memory. A [FAISS index](https://github.com/facebookresearch/faiss/wiki/guidelines-to-choose-an-index) still consumes RAM and must be budgeted; [PyG neighbor sampling](https://pytorch-geometric.readthedocs.io/en/latest/tutorial/neighbor_loader.html) bounds neighborhoods but does not eliminate their growth. Fail clearly if requested dependencies or sampling kernels are unavailable; never silently substitute dense all-pairs search.

## I: held-out fusion and anti-collapse routing

Start with frozen pretrained SRM/RGB experts and add the reconstruction expert when available. Optional VLM, metric or frequency experts use the same ID-aligned cache/score contract. Each expert retains its declared class polarity. Main prediction is a probability mixture `p_fake = sum(g_e * p_fake_e)`, exposed as `[log(1-p_fake), log(p_fake)]` with documented numerical bounds. This differs from the legacy logit mixture and must be named accordingly. Include each expert, arithmetic mean, legacy geometric-fake mean, normalized two-class geometric fusion as a separately named option, and persisted logistic stacking.

Deterministically hash validation source IDs into approximately 50% `val_fit` and 50% `val_select`, with a fixed salt and no split search. Keep related views/groups together, check both classes and fail if the split is invalid. Fit router/stacker and their normalization/calibration parameters only on `val_fit`; use `val_select` for the limited configuration shortlist, early stopping and frozen threshold. Use these same partitions for every learned combination, including pairwise complementarity experiments. Never fit on overconfident HF train predictions. Do not refit on all val after selection without a new calibration plan.

The existing evaluator requires source split `val`; retain that split and add explicit partition role, parent manifest hash, partition hashes and policy to certificates. The lead must enforce role checks so generic calibration cannot silently use `val_fit` for a learned fusion. The HF experts were already checkpoint-selected on full val, so this division does not remove inherited checkpoint-selection optimism. Truly independent stacking would require held-out expert-training data or out-of-fold expert predictions; acknowledge that server-scale extension rather than claim an unbiased local holdout.

Use a small router: a logits/confidence-only baseline, then per-expert feature projections to 16 dimensions and a 32-hidden-unit MLP. Start soft with temperature 1; test top-2 only after warm-up. Compute router softmax in FP32; expose differentiable dense probabilities and auxiliary losses, while detaching only diagnostics. For sparse routing adapt [Switch's balancing term](https://www.jmlr.org/papers/v23/21-0998.html) as `E * sum(f_e * P_e)`, where `P` is pre-mask mean router probability and `f` is detached assignment fraction normalized across B*k selections. For dense routing compare a squared deviation of mean mass from `1/E`. Balancing, dropout and temperature are controlled ablations, not a demand that all experts be equally useful.

Use expert dropout with at least two available experts while training top-2/soft, dense warm-up and a small balancing coefficient. Log per-expert mean mass, selection count, per-sample entropy, effective expert count, loss components and gradients. Renormalized top-1 has weight exactly one and zero task gradient into the router: initially support top-1 at inference after soft training; any top-1 training needs an explicitly tested straight-through/surrogate design. A top-k fusion over precomputed expert features is sparse aggregation, not reduced backbone inference cost. Do not claim conditional compute savings.

Implementation order: exact cache and prediction contract, same-feature baselines, G, H baselines/static graphs then dynamic/sampled support, I simple fusion then router. This order permits useful rejection before expensive or statistically weak variants while preserving tested implementations for all requested model families.
